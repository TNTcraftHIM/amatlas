做一个新游戏。需求:$ARGUMENTS

## 第 0 步：工位已有作品或状态？（防覆盖，最先查）

先分别检查 `src/world.js`、根 `PROGRESS.md` 与根 `canon.md` 是否存在。任一存在都说明工位可能已有作品或 pre-world 状态，**立即停下并让用户三选一**；不能因为缺少 `src/world.js` 就把工位当成空白：

1. **继续旧作**：本命令不再创建新作。已有 `src/world.js` 时改用 `/polish-game`；只有 pre-world 状态时，读取合法 current 与相关 `canon.md`，按其中已确认的下一步恢复原创作，需要工作流时仍路由 `text-adventure-game` skill。
2. **归档旧作**：先确认归档目标；`src/` 存在时将整个目录移到 `archive/<游戏名>/`，只有 pre-world 状态时也可只归档其根状态文件。对根 `PROGRESS.md` 与 `canon.md` 逐一处置：确认属于该作品的必须一并移入归档；确认无关的保留；归属不确定时停下询问，不能带着不确定的旧状态继续。目标已存在时不得覆盖。
3. **覆盖旧作**：只有用户明确确认“覆盖”后才可继续。确认内容必须分别列明现存 `src/`、属于旧作的根 `PROGRESS.md` 与 `canon.md`；确认后将它们删除或移到用户批准的备份位置，不能留在根目录进入新作。确认无关的文件保留；归属不确定时停下询问。

进入第 1 步前，根目录不得残留已确认属于被归档或覆盖旧作的 `PROGRESS.md` / `canon.md`，也不得有归属未决的同名文件。

端用户包可能没有 git，覆盖会造成不可逆丢失。要并行制作第二部游戏，优先按 README「做第二部游戏」复制整个引擎文件夹。

## 第 1 步：解析本次命令参数

把 `$ARGUMENTS` 原样视为用户的题材、玩法或改编素材要求；参数为空时，只补问完成创作所需的最小需求，不自行扩张范围。

## 第 2 步：调用唯一创作工作流

读取并执行 `.claude/skills/text-adventure-game/SKILL.md`。类型路由、素材改编、规模与 canon 策略、五阶段工作流均以该 skill 为准，不在本 command 另建分支或旁路。

需要可执行 JS / HTML 起点时，使用该 skill 指向的正式 `examples/` 文件；需要能力词汇或清单时，读取该 skill 路由的 `references/`，不要在本 command 复制模板或数量。
